context document for standing up HDX-MS data. \

Most up to date information: \
proposed approach was to **use an existing mass-spectrometry repository for storage**—with metadata pointing to PRIDE—while building HDX-specific analysis and visualization tools on top, rather than duplicating the storage.

- Start with a **rough-draft format**, not a closed schema. Include fields such as experiment type and conditions, then refine it with community input and the first dataset.

- Reduce deposition friction: let researchers upload a paper’s methods section, have an agent extract metadata, and prompt them to fill in missing required information.

- Support the common continuous-labeling workflow: compare conditions, apply researcher-specific quality filters, and map peptide-level changes in rigidity or flexibility onto a structure. He also envisioned interactive views where users choose a PDB structure and time points.

<https://www.ebi.ac.uk/pride/> is a very good resource. people should deposit there and we should have an analysis workflow rooted by protein that cites the correct pride identifier. eventually this will be linked to dynamicpdb.com but not right now.

The mHDX-MS datasets in Ferrari et at (2025) are provided under a Creative Commons 4.0 license at Zenodo (<https://doi.org/10.5281/zenodo.14983481>) To try to make use of the data as frictionless as possible, the data can be immediately downloaded and reshared without any registration.

The code for the analyses can be found at GitHub (<https://github.com/Rocklin-Lab/mhdx_pipeline>; <https://github.com/Rocklin-Lab/hdxrate_pipeline>; and <https://github.com/Rocklin-Lab/mhdx_analysis>).
